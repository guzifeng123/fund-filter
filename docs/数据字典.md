# 数据字典

文档版本：v1.5
日期：2026-07-14
适用范围：当前 PostgreSQL schema 与本地测试 SQLite schema。字段以 `apps/api/app/db/models.py` 和 Alembic 当前 head `0009_add_llm_provider_events` 为准。

## 1. 通用约定

- 时间字段默认使用带时区时间，后端以 UTC 写入。
- JSON 字段在 PostgreSQL 使用 JSONB，在 SQLite 测试环境降级为 JSON。
- 当前个人版默认 `user_id` 为 `local-user`，后续接入账号体系后应从鉴权上下文注入。
- `fund_navs.trade_date` 保持字符串兼容层：只有 `sample_local` 可使用 `YYYY`，真实来源必须使用完整 ISO `YYYY-MM-DD`。`trade_date_precision` 显式记录 `year/day/unknown`；迁移不会把年份猜测为某个具体交易日。
- 基金资料、净值和指标都带 `snapshot_generation_id`。业务读取只接受 `fund_data_snapshot_state.id=1` 指向的 active generation；同步先写候选 generation，校验成功后在同一事务末尾晋升。

## 2. 基金基础表 `funds`

用途：保存基金基础资料、费用、风险等级、数据来源和 AI 摘要。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | string | 基金代码，主键。 |
| `name` | string | 基金名称，支持搜索索引。 |
| `fund_type` | string | 基金类型，例如 `mixed`、`bond`、`stock`。 |
| `risk_level` | string | 基金风险等级，取值 R1-R5。 |
| `manager_name` | string | 基金经理名称。 |
| `inception_date` | date | 成立日期。 |
| `fund_size_billion` | float | 基金规模，单位：亿元。 |
| `management_fee` | float | 管理费率，单位：%。 |
| `custody_fee` | float | 托管费率，单位：%。 |
| `source` | string | 稳定数据来源，例如 `sample_local`、`public_http_json`、`eastmoney_snapshot`。 |
| `data_updated_at` | datetime | 基金资料更新时间，用于前端新鲜度展示。 |
| `ai_summary` | text | AI 摘要或占位说明。 |
| `raw_data` | json | profile 写入面的规范化 payload 快照；包含可用的 `provider_profile` / `upstream_provider`，不混入净值和指标数组。 |
| `snapshot_generation_id` | string | 当前行所属基金数据 generation；基金读取必须与 active state 一致。 |
| `created_at` | datetime | 创建时间。 |
| `updated_at` | datetime | 更新时间。 |

关联：一只基金有多条 `fund_navs`，最多一条 `fund_metrics`。

## 3. 基金净值表 `fund_navs`

用途：保存基金历史净值点，供净值曲线、回测和指标计算使用。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键。 |
| `fund_code` | string | 关联 `funds.code`。 |
| `trade_date` | string | 交易日；legacy sample 为 `YYYY`，真实日频 profile 为 ISO `YYYY-MM-DD`。 |
| `trade_date_precision` | string | 日期精度：`year` 表示 legacy sample 年度点，`day` 表示真实 ISO 交易日，`unknown` 仅标记迁移时无法安全分类的历史值。 |
| `nav` | float | 单位净值。 |
| `accumulated_nav` | float | 累计净值。 |
| `raw_data` | json | 单个净值点的规范化 payload、来源、日期精度和该点的 `quality_warnings`。 |
| `snapshot_generation_id` | string | 当前净值点所属 generation；必须与同次候选快照的基金行一致。 |

约束：`fund_code + trade_date` 唯一；基金删除时级联删除净值。

质量规则：零、负数、`NaN`、无穷值和真实来源的非 ISO 日期始终拒绝。正数异常区间默认只告警；当前默认单位净值 `[0.01, 100]`、累计净值 `[0.01, 1000]`，可用环境变量调整，并通过 `FUND_NAV_REJECT_ANOMALIES=true` 开启整次同步拒绝。迁移 `0007_add_nav_trade_date_precision` 只分类不改写 `trade_date`，可重复执行 Alembic `upgrade head`，downgrade 也不改变原日期值。

| `max_drawdown` | float | 最大回撤，单位：%。 |

| `category_rank_percentile` | float | 同类排名分位，数值越小排名越靠前。 |
| `manager_years` | integer | 基金经理从业或管理年限。 |
| `raw_data` | json | metrics 写入面的原始 payload 或计算快照；不覆盖 profile/nav。 |
| `snapshot_generation_id` | string | 当前指标行所属 generation；active 基金必须有同 generation 指标。 |

## 4.1 基金数据快照表 `fund_data_snapshots`

用途：记录每次完整基金数据候选及其晋升状态。当前记录保存导入计数和来源摘要，不承诺历史 generation 的逐行数据永久可回放。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `generation_id` | string | generation 主键，例如 `snapshot-...`；迁移前数据统一回填为 `legacy-0008`。 |
| `source` | string | 本次完整快照的数据源；多 legacy 来源使用有界摘要 `mixed(N sources)`。 |
| `status` | string | 当前应用写入 `staging`、`active` 或 `superseded`。 |
| `fund_count` | integer | 候选基金行数。 |
| `nav_count` | integer | 候选净值行数。 |
| `metric_count` | integer | 候选指标行数。 |
| `created_at` | datetime | 候选记录创建时间。 |
| `promoted_at` | datetime/null | 成功晋升时间；staging 时为 null。 |

## 4.2 基金数据快照状态表 `fund_data_snapshot_state`

用途：保存唯一 active generation 指针。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 固定为 `1`；数据库 CHECK 约束禁止第二个 state ID。 |
| `active_generation_id` | string | 外键关联 `fund_data_snapshots.generation_id`，并保持唯一。 |
| `updated_at` | datetime | 最近晋升时间。 |

读取实现把该指针作为标量子查询嵌入基金数据 SQL，使单条语句中的指针和行集合处于同一数据库快照。多语句响应元数据与历史逐行回放仍是后续不可变 generation 表需要解决的边界。

## 5. 风险测评表 `risk_assessments`

用途：保存用户风险测评结果。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键。 |
| `user_id` | string | 用户标识，当前默认 `local-user`。 |
| `risk_profile` | string | 用户风险承受等级，取值 C1-C5。 |
| `answers` | json | 当前写入 `{score, items}`；`items` 保存 6 道现行题目的唯一 `question_id` 与 `score`，重复题目在请求校验阶段拒绝。 |
| `assessed_at` | datetime | 测评时间。 |

有效期规则：repository 从 `assessed_at` 起加固定 365 天得到 `effective_to`，并在到期前 30 天（含）返回 `expires_soon=true`；`effective_to < now` 时返回 `is_expired=true`。`effective_from`、`effective_to`、`expires_soon`、`is_expired` 和 `explanation` 都是 API 派生字段，不是当前表的列。设置 API 把 365 天换算为 12 个月用于展示，但底层不是按自然月计算。

## 7. 组合持仓表 `portfolio_positions`

用途：保存组合内基金权重。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键。 |
| `portfolio_id` | string | 关联 `portfolios.id`。 |
| `fund_code` | string | 关联 `funds.code`。 |
| `weight_percent` | float | 持仓权重，单位：%。 |
| `metadata` | json | 持仓扩展信息，ORM 字段名为 `metadata_`。 |

约束：`portfolio_id + fund_code` 唯一；基金被持仓引用时限制删除。

API 派生字段：`positions[].available` 表示关联基金是否仍属于 active snapshot generation，`positions[].availability_reason` 当前取 `available` 或 `removed_from_active_snapshot`，`unavailable_position_count` 表示组合内不可用持仓数；这些字段都不是数据库列。基金从 active generation 移除时保留既有持仓和关联基金行，用户仍可删除该持仓，但服务端不会使用旧基金分类继续计算派生比例。

归一化规则：`POST /api/portfolios/{portfolio_id}/positions/normalize` 在单个数据库事务中按当前相对权重写回 100%；前 N-1 条保留 6 位小数，最后一条吸收舍入差。空组合或总权重不大于 0 时拒绝操作，不写入部分结果；存在任一不可用持仓时返回 `409 PORTFOLIO_HAS_UNAVAILABLE_POSITIONS`，`error.detail` 返回 `availability_reason` 与 `unavailable_fund_codes`。再平衡预览使用相同的不可用持仓阻断合同。

## 8. 回测表 `backtest_runs`

用途：保存回测请求和结果快照，确保结果可追溯。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 回测 ID，主键。 |
| `user_id` | string | 用户标识，当前默认 `local-user`。 |
| `strategy_type` | string | 策略类型，当前为 `weekly_dca`、`monthly_dca`、`rebalance`、`template_portfolio`。 |
| `request_payload` | json | 回测输入参数快照。 |
| `result_snapshot` | json | 回测结果曲线、指标、数据提示和本次读取的 `snapshot_generation_id`。 |
| `annualized_return` | float | 年化收益率，单位：%。 |
| `max_drawdown` | float | 最大回撤，单位：%。 |
| `volatility` | float | 波动率，单位：%。 |
| `created_at` | datetime | 创建时间。 |

读取口径：创建回测时先解析一次 active fund-data generation，再用该 generation 加载 NAV 和基金类型；`snapshot_generation_id` 随结果快照持久化。读取历史回测时 API meta 的来源和更新时间按该 generation 计算，不按查询时最新 active generation 重标。

## 9. 数据任务表 `job_runs`

用途：记录 seed、同步、指标计算等任务的运行状态。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键。 |
| `name` | string | 任务名，例如 `sync_fund_navs`。 |
| `status` | string | 任务状态，当前应用层使用 `running`、`success`、`failed`。 |
| `started_at` | datetime | 开始时间。 |
| `finished_at` | datetime/null | 结束时间。 |
| `details` | json | 任务摘要、计数、错误详情；基金同步成功时包含 `requested_task`、`effective_scope=full_snapshot`、`generation_boundary=atomic_promotion`、新旧 generation ID 和 `snapshot_quality_thresholds`。 |

约束：部分唯一索引 `uq_job_runs_running_name` 保证同一任务名最多一条 `status='running'` 记录。超过 `FUND_SYNC_LOCK_TIMEOUT_MINUTES` 的运行记录会在新任务启动前标记为 failed，避免进程崩溃留下永久锁。

后续优化：如有多语言写库，应增加数据库 CHECK 约束或 PostgreSQL enum。

## 14. LLM Provider 事件表 `llm_provider_events`

用途：保存真实 LLM provider 请求的最小化可观测元数据，用于最近窗口的可用性、错误、重试和超时统计。`mock` 路径不调用 provider，因此不产生事件。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 自增主键。 |
| `provider_name` | string | 仅允许安全标识符；密钥/token/JWT、URL、裸 hostname/host:port、credential-like 或过长值统一保存为 `unknown`。 |
| `model_name` | string | 与 provider 相同的安全净化规则，最大 128 字符。 |
| `outcome` | string | `success` 或 `fallback`。缺配置、最终调用失败或输出策略拒绝均使用回退结果。 |
| `attempt_count` | integer | 本次请求实际发起的网络尝试数；缺配置时为 `0`。 |
| `retry_count` | integer | 重试次数；`attempt_count=0` 时必须为 `0`，否则满足 `0 <= retry_count < attempt_count`。 |
| `latency_ms` | integer | provider 请求从进入客户端到最终结果的总耗时，单位毫秒，非负。 |
| `timed_out` | boolean | 任一尝试是否发生超时；重试后成功仍保留该标记。 |
| `error_category` | string/null | 仅允许 `config_missing`、`timeout`、`network`、`rate_limited`、`http_client`、`http_server`、`invalid_response`、`policy_rejected`、`provider_error`；`fallback` 时不能为空。 |
| `created_at` | datetime | provider 调用完成时在请求线程生成的 UTC 事件时间，用于最近窗口过滤；异步 worker 原样落库，不代表实际写库时间。 |

索引：`ix_llm_provider_events_provider_model_created_at` 按当前 provider/model 和时间窗口聚合。数据库 CHECK 同时限制标签长度/基本危险分隔符、尝试与重试关系、非负延迟、错误类别、fallback 类别，以及 `attempt_count=0` 只能表示 `config_missing`。

事件表禁止保存 prompt、响应正文、异常原文、URL、API key、token 或凭据。主路径只非阻塞写入固定容量内存队列，单一 daemon worker 执行数据库事务；队列满、写入失败、worker 意外退出或关闭 drain 超时均不能中断或延迟聊天结果。worker 只允许在同一 dispatcher 的同一有界队列上受控重启；关闭超时后只能丢弃尚未开始处理的队列遗留事件并计数。队列丢弃只按数量汇总，不在请求线程同步记录 provider/model 标签。

事件保留：`LLM_OBSERVABILITY_RETENTION_DAYS` 控制保留天数，默认 30 天。`scripts/cleanup_llm_provider_events.py` 默认 dry-run，只统计 `created_at` 早于截止时间的旧事件；显式传入 `--apply` 后才批量删除，并可通过 `--json-report-path` 输出 `schema_version=1` 的聚合清理报告。报告只包含保留天数、截止时间、匹配数、删除数和剩余数，不包含 provider/model 明细或事件 payload。

## 15. 未落库的未来概念

| 概念名称 | 当前状态 |
| --- | --- |
| `portfolio_snapshots` | 未来组合每日快照概念；当前组合配置在 `portfolios` / `portfolio_positions`，回测快照在 `backtest_runs.result_snapshot`。 |
