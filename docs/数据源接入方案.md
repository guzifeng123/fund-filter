# 数据源接入方案

当前版本已经具备数据源 adapter 边界，但仍默认使用 `sample_local` 数据。

## 净值日期与质量合同

- `sample_local` 是唯一允许使用 `YYYY` 年份字符串的来源，用于保留现有年度样本回测；真实来源（包括 `csv_local`、`public_http_json` 及其 provider profile）必须提供完整、有效且规范化的 ISO `YYYY-MM-DD`。
- schema 先拒绝无效日历日期、非规范日期、零/负净值、`NaN` 和无穷值；公开 JSON 的远程 `navs/{code}.json` 与 repository 写入边界会再次检查真实日期，避免 Pydantic 对象被赋值修改后绕过来源约束。
- 数据库继续保留字符串 `trade_date` 以兼容年度样本；迁移 `0007_add_nav_trade_date_precision` 新增 `trade_date_precision=day/year/unknown`，只对能无歧义识别的现有值分类，不改写用户数据。`unknown` 供历史异常值审计，不代表新同步允许写入异常日期。
- 正数净值的异常区间由 `FUND_NAV_VALUE_MIN` / `FUND_NAV_VALUE_MAX` 与 `FUND_ACCUMULATED_NAV_VALUE_MIN` / `FUND_ACCUMULATED_NAV_VALUE_MAX` 控制，默认分别为 `[0.01, 100]` 和 `[0.01, 1000]`。越界默认告警但仍可写入；`FUND_NAV_REJECT_ANOMALIES=true` 时，任一越界值会拒绝并回滚整次候选快照，旧 active generation 继续可见。
- 告警写入 `job_runs.details.quality_warnings`（最多保留前 100 条并提供总数/截断标记），同时写入对应 `fund_navs.raw_data.quality_warnings`。CSV 预检报告也返回 `quality_warnings`；开启拒绝模式时 `ok=false`。
- 快照级晋升阈值由 `FUND_SNAPSHOT_MIN_FUND_COUNT`、`FUND_SNAPSHOT_MIN_NAV_COVERAGE_RATIO`、`FUND_SNAPSHOT_MAX_LATEST_NAV_AGE_DAYS` 和 `FUND_SNAPSHOT_MAX_FUND_COUNT_DROP_RATIO` 控制。默认只要求至少 1 只基金，其余检查关闭或允许 100% 下降，便于 sample/local 降级；真实 provider 可在部署环境中收紧。
- `FUND_SNAPSHOT_QUALITY_OVERRIDES` 可用 JSON 按 adapter `source.name` 或候选基金持久化 `source` 覆盖阈值，例如 `{"eastmoney_snapshot":{"min_fund_count":100,"min_nav_coverage_ratio":0.9,"max_latest_nav_age_days":7,"max_fund_count_drop_ratio":0.2}}`。任一阈值失败会在写入候选数据前拒绝晋升，旧 active generation 继续可见，失败原因进入 `job_runs.details.error`。

## 当前数据源

### sample_local

- 实现位置：`apps/api/app/data_sources/sample_local.py`
- 数据来源：`apps/api/app/services/sample_data.py`
- 用途：本地开发、测试、无外部依赖降级
- 新鲜度边界：源码 fixture 保留固定历史日期以支持确定性测试；执行 `python -m app.jobs.seed_sample_data` 时，只覆盖本次写入 sample profile 的 `data_updated_at` 为当前 UTC，不改写净值日期或伪装成真实上游更新时间。`smoke-api.ps1 -SeedIfEmpty -RequireFresh` 因而可验收新建 sample 环境，同时真实 provider 仍必须使用自己的上游时间并满足同一 freshness 门禁。
- 能力：
  - `fetch_snapshot`
  - `fetch_fund_profiles`
  - `fetch_fund_navs`
  - `fetch_risk_levels`

### csv_local

- 实现位置：`apps/api/app/data_sources/csv_local.py`
- 数据来源：`FUND_CSV_DIR` 目录下的 `funds.csv` 和 `navs.csv`
- 用途：从 sample 过渡到真实数据前的离线、可审计数据接入
- 能力：
  - `fetch_snapshot`
  - `fetch_fund_profiles`
  - `fetch_fund_navs`
  - `fetch_risk_levels`

`funds.csv` 必填字段：

```text
code,name,fund_type,risk_level,manager_name,inception_date,fund_size_billion,management_fee,custody_fee,annualized_return_3y,annualized_return_5y,max_drawdown,sharpe_ratio,category_rank_percentile,manager_years,data_updated_at,ai_summary
```

`navs.csv` 必填字段：

```text
fund_code,trade_date,nav,accumulated_nav
```

### public_http_json

- 实现位置：`apps/api/app/data_sources/public_http_json.py`
- 数据来源：`PUBLIC_FUND_DATA_BASE_URL` 指向的公开 HTTP/静态 JSON 目录
- 用途：公开数据源第一版 adapter，适合先接入可审计的静态 JSON 镜像，再逐步替换为具体站点字段映射
- 能力：
  - `fetch_snapshot`
  - `fetch_fund_profiles`
  - `fetch_fund_navs`
  - `fetch_risk_levels`

配置：

```powershell
FUND_DATA_SOURCE=public_http_json
PUBLIC_FUND_DATA_BASE_URL=https://example.com/funds/
PUBLIC_FUND_DATA_PROFILE=generic_aliases_v1
PUBLIC_FUND_DATA_TIMEOUT_SECONDS=10
PUBLIC_FUND_DATA_CACHE_DIR=.cache/public-fund-data
PUBLIC_FUND_DATA_MIN_INTERVAL_SECONDS=0.2
PUBLIC_FUND_DATA_BATCH_SIZE=100
PUBLIC_FUND_DATA_MAX_PAGES=100
FUND_NAV_VALUE_MIN=0.01
FUND_NAV_VALUE_MAX=100
FUND_ACCUMULATED_NAV_VALUE_MIN=0.01
FUND_ACCUMULATED_NAV_VALUE_MAX=1000
FUND_NAV_REJECT_ANOMALIES=false
FUND_SNAPSHOT_MIN_FUND_COUNT=1
FUND_SNAPSHOT_MIN_NAV_COVERAGE_RATIO=0
FUND_SNAPSHOT_MAX_LATEST_NAV_AGE_DAYS=0
FUND_SNAPSHOT_MAX_FUND_COUNT_DROP_RATIO=1
FUND_SNAPSHOT_QUALITY_OVERRIDES=
```

`funds.json` 可以是数组，也可以是 `{ "funds": [...] }`。分页数据可以返回 `next` / `next_path` / `nextPath`，或返回 `page` + `total_pages`，adapter 会继续读取后续页。所有分页地址必须与 `PUBLIC_FUND_DATA_BASE_URL` 保持相同协议、主机和有效端口，不允许内嵌用户信息；adapter 会拒绝循环分页，并以 `PUBLIC_FUND_DATA_MAX_PAGES` 限制单次读取页数。每个基金对象经所选 profile 归一化为 `FundDetail`；`navs`、`ai_summary`、`metric_explanations` 可省略。

字段归一化位于 `apps/api/app/data_sources/profiles/`，transport adapter 不再保存站点别名。registry 当前提供：

| profile | 输入合同 | 最终来源标识 |
| --- | --- | --- |
| `generic_aliases_v1` | 默认兼容 profile；支持原标准字段及历史 `fundCode`、`fundName`、`fundType`、`tradeDate`、`unitNav` 等常见别名 | `source=public_http_json`，`provider_profile=generic_aliases_v1` |
| `normalized_v1` | 只接受已经归一化的 `FundDetail` / `NavPoint` 字段名，不应用通用别名 | `source=public_http_json`，`provider_profile=normalized_v1` |
| `eastmoney_snapshot_v1` | `EastmoneySnapshotBuilder` 生成的标准、带审计元数据镜像 | `source=eastmoney_snapshot`，`provider_profile=eastmoney_snapshot_v1`，`upstream_provider=eastmoney` |

新增站点或格式时实现 profile 协议并注册即可，不需要修改 `PublicHttpJsonFundDataSource`。未知 `PUBLIC_FUND_DATA_PROFILE` 会在 adapter 构造时列出支持项并立即失败。

HTTP 行为：

- 若配置 `PUBLIC_FUND_DATA_CACHE_DIR`，adapter 会持久化响应正文及 `ETag` / `Last-Modified` 元信息。
- 后续请求会带上 `If-None-Match` / `If-Modified-Since`，遇到 304 时复用本地缓存。
- `PUBLIC_FUND_DATA_MIN_INTERVAL_SECONDS` 用于控制同一 adapter 实例内的最小请求间隔，避免同步时过快打满公开接口。
- `PUBLIC_FUND_DATA_PROXY_URLS` 可选配置由运维方提供的 HTTP(S) 代理列表，多个地址按请求轮询使用。系统不会自动抓取公共代理列表、探测匿名代理或以代理轮换规避上游访问限制；代理不可用时请求会失败并保留旧快照。
- `PUBLIC_FUND_DATA_BATCH_SIZE` 用于 `page` + `total_pages` 风格分页的下一页参数生成。
- `PUBLIC_FUND_DATA_MAX_PAGES` 默认 100；到达上限后若上游仍声明下一页，adapter 会拒绝继续请求并给出配置提示。

如果基金对象没有内联 `navs`，`fetch_fund_navs` 会尝试读取：

```text
navs/{code}.json
```

该文件可以是数组，也可以是 `{ "navs": [...] }`，每个净值点需要包含：

```text
trade_date,nav,accumulated_nav
```

其中 `trade_date` 必须是完整 ISO `YYYY-MM-DD`；真实来源使用 `YYYY` 会被拒绝，不会被猜测为该年第一天或最后一天。

默认 `generic_aliases_v1` 的净值字段也支持常见别名：`tradeDate` / `date`、`unitNav` / `unit_nav`、`accumulatedNav` / `acc_nav`。

#### 已验收 provider profile：`eastmoney_snapshot_v1`

2026-07-13 已选择东方财富基金公开页面作为第一个“静态快照镜像”上游，并完成基金 `000001` 的真实链路验收。该 profile 不让业务 adapter 执行第三方 JavaScript，也不把第三方接口当作稳定合同；生成器只提取白名单字段，输出标准 `funds.json`、`navs/{code}.json` 和带 SHA-256 的 `manifest.json`，之后由通用 `public_http_json` transport 配合 `PUBLIC_FUND_DATA_PROFILE=eastmoney_snapshot_v1` 读取。

实现与 fixture：

- profile：`apps/api/app/data_sources/profiles/eastmoney_snapshot.py`
- 生成器：`scripts/build_eastmoney_mirror.py`
- 固定 fixture：`apps/api/app/tests/fixtures/eastmoney_snapshot/`
- 真实验收产物：`output/eastmoney-mirror/`

生成命令：

```powershell
python scripts/build_eastmoney_mirror.py `
  --fund-code 000001 `
  --output-dir output/eastmoney-mirror `
  --timeout-seconds 20 `
  --min-interval-seconds 0.2
```

2026-07-13 实测结果：1 个基金 profile、1,247 个净值点，净值区间为 `2021-05-25` 至 `2026-07-10`；生成后通过本地只读 HTTP 服务交给生产 `PublicHttpJsonFundDataSource(profile_name="eastmoney_snapshot_v1")` 再次解析，避免只验证生成器自身。写库后 `funds.source` 保留 `eastmoney_snapshot`，profile/upstream 信息保存在 `raw_data` 并由基金响应返回。

字段口径：

| 内部字段 | 上游字段/页面 | 转换规则 |
| --- | --- | --- |
| `code` / `name` | `FCODE` / `SHORTNAME` | 原值；基金代码必须是 6 位数字。 |
| `fund_type` | `FTYPE` | 按“股票型/混合型/债券型/货币型”前缀映射；未知类型拒绝生成。 |
| `risk_level` | `RISKLEVEL` | 上游 1-5 映射为 R1-R5；未知风险码拒绝生成。 |
| `manager_name` | `JJJL` | 保留当前经理列表。 |
| `manager_years` | 基金经理页当前“上任日期” | 以最新净值日计算完整管理年数，不用基金成立年限替代。 |
| `inception_date` | `ISSBDATE` | 截取 ISO 日期部分。 |
| `fund_size_billion` | `ENDNAV` | 上游人民币元除以 `100,000,000`，内部实际展示单位为亿元。 |
| `management_fee` / `custody_fee` | 基金概况页“管理费率/托管费率” | 提取年费率百分数；任一缺失即拒绝生成，不补 0。 |
| `annualized_return_3y/5y` | `LJJZ` 历史累计净值 | 目标日优先取当日或之前最近交易日，按实际天数 CAGR 计算；覆盖不足拒绝生成。 |
| `max_drawdown` | `LJJZ` | 在镜像净值窗口内按历史峰值计算。 |
| `sharpe_ratio` | `LJJZ` 日收益 | 无风险利率暂按 0，样本标准差，按 250 个交易日年化；此假设必须随指标展示。 |
| `category_rank_percentile` | `RANKY / YSC` | 当前使用上游近 1 年同类排名/同类总数，数值越小越靠前。 |
| `data_updated_at` | 镜像生成时间 | 带 `+08:00` 时区；最新净值日期仍以 `navs` 最后一条为准。 |

上游边界：

- 基础资料：`fundmobapi.eastmoney.com/FundMApi/FundBaseTypeInformation.ashx`
- 历史净值：`api.fund.eastmoney.com/f10/lsjz`，实测单页上限为 20；超过上限可能返回 `Data=null`。
- 费率与经理任期：`fundf10.eastmoney.com` 的公开 F10 页面。
- 这是公开页面快照，不是官方承诺的稳定 API；只用于个人、本地、低频验证，默认最小请求间隔 0.2 秒，不绕过认证或反爬限制。
- 页面结构、字段或使用条款变化时必须停止生成并重新验收，不允许静默填充缺失字段。

失败回退演练已加入自动化测试：镜像读取抛错时，同步任务写入 `job_runs.failed`，已有基金和净值行数保持不变。对应测试为 `test_failed_public_mirror_sync_preserves_old_rows`。

失败行为：

- `PUBLIC_FUND_DATA_BASE_URL` 为空时直接报错。
- `PUBLIC_FUND_DATA_PROFILE` 未注册时在构造 adapter 阶段直接报错，并列出支持的 profile。
- HTTP、JSON 解析或字段校验失败时抛出异常，由同步任务写入 `job_runs.failed`。
- adapter 不直接写库，因此失败时不会覆盖已有可用数据。

### eastmoney_direct（在线直连）

- 实现位置：`apps/api/app/data_sources/eastmoney_direct.py`
- 用途：在没有静态镜像的环境里，低频在线抓取东方财富公开页面，经同一个 `EastmoneySnapshotBuilder` 解析后进入既有原子快照晋升。
- 与 `eastmoney_snapshot_v1`（离线审计镜像）并存：后者由 `scripts/build_eastmoney_mirror.py` 产出静态文件后交给 `public_http_json` 读取；前者在线直连、带本地历史缓存做增量净值合并。两者产出的 `source=eastmoney_snapshot / provider_profile=eastmoney_snapshot_v1 / upstream_provider=eastmoney` 字段口径一致。
- 能力：
  - `fetch_snapshot` / `fetch_fund_profiles` / `fetch_fund_navs`（本源指标依赖净值序列，三者均返回完整快照）
  - `fetch_risk_levels`
  - `health_check`（单端点最小探活）

配置：

```powershell
FUND_DATA_SOURCE=eastmoney_direct
FUND_EASTMONEY_FUND_CODES=000001,110011
FUND_EASTMONEY_TIMEOUT_SECONDS=15
FUND_EASTMONEY_MIN_INTERVAL_SECONDS=0.5
FUND_EASTMONEY_CACHE_DIR=.cache/eastmoney-direct
FUND_EASTMONEY_ENABLE_INCREMENTAL=true
FUND_EASTMONEY_DISCOVERY_LIMIT=0
FUND_EASTMONEY_ENABLE_HEALTH_CHECK=true
```

关键边界：

- **绝不静默全市场抓取**：基金清单来自 `FUND_EASTMONEY_FUND_CODES` 显式代码；只有 `FUND_EASTMONEY_DISCOVERY_LIMIT>0` 才会通过 AKShare 排名发现候选，且受数量上限约束。两者都为空/关闭时，adapter 在构造阶段直接 `ValueError` 失败。代码必须是 6 位数字，非法配置立即失败。
- **增量净值**：开启 `FUND_EASTMONEY_ENABLE_INCREMENTAL` 且配置 `FUND_EASTMONEY_CACHE_DIR` 时，按本地缓存中每只基金最新净值日作为 `lsjz` 的 `startDate`，只拉新增页，与缓存历史按 `FSRQ` 去重合并后再走既有 `build_fund_snapshot` 校验（3/5 年年化、最大回撤、夏普等仍基于完整合并历史）。无法判定增量起点（无缓存、缓存损坏、增量关闭）时回退全量，并在 `job_runs.details.source_run_report.funds[].nav_fetch_mode=full` 与 `fallback_reason` 中标注。
- **发现/单基金失败**：AKShare 发现失败或被发现基金 3/5 年历史不足/上游报错时，结构化记录到 `job_runs.details.source_run_report.skipped` 并跳过；显式配置的基金失败则整次同步失败、保留旧数据（原子晋升）。
- **探活**：`GET /api/data/sources/health` 只对单个 `FundBaseTypeInformation` 端点做一次最小、限速请求，返回可达性/延迟/失败原因，不写库、不触发全量拉取。当前源不支持探活时返回 `enabled=false` 与说明。
- **合规**：仅读取公开页面快照，不执行第三方 JS、不绕过认证/反爬、不伪造字段；页面结构或字段变化时该能力降级（报错或在探活中体现），不静默填充。数据保留 `source/provider_profile/upstream_provider`、数据日期与免责声明；上游失败时旧 generation 继续可见。

## Adapter 接口

统一接口位于 `apps/api/app/data_sources/base.py`：

```python
class FundDataSource(Protocol):
    name: str
    def fetch_snapshot(self) -> list[FundDetail]: ...
    def fetch_fund_profiles(self) -> list[FundDetail]: ...
    def fetch_fund_navs(self) -> list[FundDetail]: ...
    def fetch_risk_levels(self) -> dict[str, str]: ...
```

切换入口位于 `apps/api/app/data_sources/__init__.py`。默认读取：

```powershell
FUND_DATA_SOURCE=sample_local
FUND_CSV_DIR=data/funds
```

`eastmoney_direct` 额外提供可选的 `health_check()`，由 `GET /api/data/sources/health` 探测；其余源不实现该方法时探活接口返回不支持说明，不报错。

## 同步任务

任务入口位于 `apps/api/app/jobs/sync_fund_data.py`：

- `sync_fund_profiles`
- `sync_fund_navs`
- `calculate_metrics`
- `sync_risk_levels`
- `sync_all`

所有任务都会写入 `job_runs`：

- `running`
- `success`
- `failed`

任务失败时会把错误写入 `details.error`。迁移 `0008_add_snapshot_generation` 增加 `fund_data_snapshots`、单例 `fund_data_snapshot_state` 以及三张基金数据表的 `snapshot_generation_id`。同步流程为：

1. adapter 通过一次 `fetch_snapshot()` 取得完整 profile/NAV/metric 集合；空集合和重复基金代码直接拒绝。
2. 在同一数据库事务内创建 `staging` generation，按 `upsert_fund_profile`、`upsert_fund_metrics`、`upsert_fund_navs` 三个最小 repository 边界写入。
3. 提交前核对基金、净值、指标行数，并拒绝缺失指标或跨 generation 的孤立 NAV/metric。
4. 所有写入成功后才把单例 state 指向新 generation；同一事务内任一晚期异常都会回滚候选行、快照记录和 active 指针。

`sync_fund_profiles`、`sync_fund_navs`、`calculate_metrics`、`sync_risk_levels` 名称为兼容已有 API/任务记录而保留，但不再原地修改 active generation。它们统一执行完整快照晋升，并在 `job_runs.details` 返回 `requested_task`、`effective_scope=full_snapshot`、`generation_boundary=atomic_promotion`、新旧 generation ID 和三类计数。调度器与 seed 均直接使用 `sync_all`。

净值质量校验在候选写入阶段执行。默认告警模式下任务仍为 `success`，details 给出 `quality_warning_count`、`quality_warnings`、`quality_warnings_truncated`；拒绝模式下任务为 `failed`，候选事务回滚，旧 generation 继续可见。

手动运行：

```powershell
python -m app.jobs.sync_fund_data
```

## 后续数据源候选

### 本地 CSV

已提供第一版 `csv_local` adapter。repository 的 profile/nav/metrics 最小写入面已经拆分，任务层则统一以完整快照原子晋升；后续剩余的是 CSV 输入文件/adapter payload 是否也拆成独立资料、净值和指标合同，而不是重复拆 repository。日期、首尾空白、指标范围和时区等严格语义校验已完成，新增口径必须继续补 fixture 与行号错误测试。

当前已经支持：

- 必填列预检，缺列时返回缺失字段列表。
- 必填字段空值报错。
- 数值字段转换失败时返回文件名、行号和字段名。
- 导入前 JSON 预检报告。
- 跨文件一致性检查：`navs.csv` 中出现 `funds.csv` 不存在的基金代码会报错。
- 唯一性检查：重复基金代码、重复“基金代码 + 净值日期”会报告重复行和首次出现行。
- 字符串字段会先去除首尾空白，再执行必填、跨文件引用和唯一性检查。
- `inception_date`、`trade_date` 使用 ISO 日期校验，`data_updated_at` 使用带时区偏移的 ISO 日期时间校验，无效日历日期或缺失时区会在预检阶段拒绝。
- 数值拒绝 `NaN`/无穷值；净值必须为正，规模必须非负，费用/排名必须在 0-100，最大回撤必须在 -100 到 0，经理年限必须为非负整数。正净值超出配置区间属于质量告警，是否拒绝由 `FUND_NAV_REJECT_ANOMALIES` 决定。

### 公开站点字段映射

`public_http_json` transport 已补充条件缓存、基础限速和安全分页；字段别名与具体站点口径由独立 profile 负责。后续新增站点仍需逐站点确认：

- 优点：覆盖范围更大
- 风险：接口稳定性、频率限制、字段口径变化
- 建议：失败时不要覆盖已有可用数据，只记录 `job_runs.failed`；新增字段映射时同步补充 adapter 单测和字段来源文档。
- 分页已强制同源、visited URL 去环和最大页数保护，跨域/协议切换/端口切换/内嵌用户信息的 `next` 均会被拒绝。
- profile 会把 `source`、`provider_profile`、`upstream_provider` 写入规范化结果；repository 将其保留到 profile/metrics/nav `raw_data`，避免标准化后隐去最终上游。

### 盈米 MCP

适合作为后续专业数据接入边界：

- 优点：业务语义更接近基金场景
- 风险：需要明确认证、调用限额、错误重试和字段授权范围
- 建议：单独实现 `YingmiMcpFundDataSource`，不要让业务路由直接调用 MCP

## 接入原则

- adapter 只负责 HTTP/JSON 读取、缓存、限速和分页，不直接操作数据库；字段转换由 profile 完成。
- 同步任务负责幂等写库、错误记录和旧数据保护。
- 指标计算必须可重复运行且结果稳定。
- 数据源失败时保留旧数据，前端通过 `/api/data/status` 和 `/api/data/jobs/recent` 查看失败原因。
- `snapshot_generation_id`、staging 记录与原子晋升已经落地；基金搜索、筛选、详情、净值、回测和数据状态读取会在数据 SQL 内解析 active 指针，避免晋升发生在“先读指针、后读数据”的语句间隙。
- 当前同一基金代码仍复用一行并在晋升时重标 generation，不提供历史 generation 的完整逐行回放。后续若需要审计历史快照或跨多语句严格一致的 response meta，应改为 generation 参与主键的不可变快照表，并增加 PostgreSQL 双 Session 晋升屏障测试。
