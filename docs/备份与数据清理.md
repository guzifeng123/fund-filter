# 备份与数据清理

文档版本：v1.0  
日期：2026-07-09  
用途：说明个人本地环境下如何备份 PostgreSQL 数据、恢复数据，以及安全清理本地生成产物或数据库数据。

## 1. 适用范围

当前 Docker Compose 数据库配置：

- 服务名：`postgres`
- 数据库：`fund_app`
- 用户：`fund_user`
- 数据卷：`postgres_data`

以下命令默认在项目根目录 `C:\Users\39187\Desktop\基金` 的 Windows PowerShell 中执行。

## 2. 备份数据库

先确认数据库容器正在运行：

```powershell
docker compose up -d postgres
```

使用脚本导出 SQL 备份：

```powershell
.\scripts\backup-db.ps1
.\scripts\backup-db.ps1 -RetentionCount 10
.\scripts\backup-db.ps1 -Compress -RetentionCount 10
.\scripts\backup-db.ps1 -Compress -RetentionCount 10 -JsonReportPath ".\output\checks\backup-report.json"
```

也可以手动执行等价命令：

```powershell
New-Item -ItemType Directory -Force .\backups
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
docker compose exec -T postgres pg_dump -U fund_user -d fund_app > ".\backups\fund_app-$stamp.sql"
```

验收：

- 备份文件存在于 `.\backups`，压缩模式输出 `.sql.gz`。
- 同名 `.sha256` 校验文件存在。
- 文件大小大于 0。
- 文件名包含导出时间，便于回滚定位。
- 如传入 `-JsonReportPath`，报告中应包含备份路径、压缩状态、校验文件、保留策略删除项和耗时。

## 3. 恢复数据库

恢复前建议先停止 API/Web，避免恢复过程中仍有写入：

```powershell
docker compose stop api web
```

使用脚本恢复指定备份。恢复脚本要求显式确认，避免误操作：

```powershell
.\scripts\restore-db.ps1 -BackupPath ".\backups\fund_app-YYYYMMDD-HHMMSS.sql" -ConfirmRestore RESTORE
.\scripts\restore-db.ps1 -BackupPath ".\backups\fund_app-YYYYMMDD-HHMMSS.sql.gz" -ConfirmRestore RESTORE
```

如果同名 `.sha256` 文件存在，恢复脚本会先校验备份文件完整性；校验不匹配时拒绝恢复。恢复脚本可直接读取 `.sql` 或 `.sql.gz`。

也可以手动执行等价命令：

```powershell
$backup = ".\backups\fund_app-YYYYMMDD-HHMMSS.sql"
Get-Content $backup | docker compose exec -T postgres psql -U fund_user -d fund_app
```

恢复后执行 smoke：

```powershell
npm.cmd run dev:api
.\scripts\smoke-api.ps1
```

## 4. 清理生成产物

清理 `.next`、`.pytest_cache`、`.ruff_cache`、`__pycache__`、`*.egg-info`、`*-dev.log` 等生成产物：

```powershell
.\scripts\clean-generated.ps1 -WhatIf
.\scripts\clean-generated.ps1
.\scripts\clean-generated.ps1 -WhatIf -SearchRoots apps,packages
.\scripts\clean-generated.ps1 -WhatIf -JsonReportPath ".\output\checks\cleanup-report.json"
```

规则：

- 先执行 `-WhatIf` 查看将删除的路径。
- 脚本只允许删除工作区内部路径。
- 默认跳过 `node_modules`、`.git`、`.venv`、`output`、`backups` 和 `.playwright-cli`，避免大型目录拖慢扫描或误删验收记录。
- 可以用 `-SearchRoots` 缩小扫描范围，例如只扫描 `apps,packages`。
- 如传入 `-JsonReportPath`，报告中会记录 `-WhatIf` 状态、搜索根、跳过目录、匹配项、实际删除项和耗时。
- 不清理 `.env`、数据库 volume、源码、文档或 contract 文件。

## 5. 清空数据库并重新初始化

危险操作：这会删除本地 PostgreSQL volume 中的数据。执行前请先确认已完成备份。

```powershell
docker compose down
$volume = docker compose config --volumes | Select-String "postgres_data"
docker volume ls
docker compose up -d postgres
.\scripts\db-migrate.ps1
python -m app.jobs.seed_sample_data
python -m app.jobs.seed_sample_data
```

上面的 `$volume` 只显示 Compose 配置中的逻辑 volume 名。实际 Docker volume 通常带项目前缀，请用以下命令确认真实名称后再删除：

```powershell
docker volume ls
docker volume rm <实际_volume_名称>
```

## 6. 本地数据清理边界

允许清理：

- 构建缓存和测试缓存。
- 本地开发日志。
- 明确备份后的 Docker 数据卷。

禁止直接清理：

- 未备份的 `postgres_data` volume。
- `.env` 和 API key。
- `packages/contracts/openapi.json`，除非重新导出并确认。
- Alembic migration 文件。
